# SUPERX_SCHEMA.md — Substrate Schema, Source of Truth (v2)

> **Status: G1 design — locked on apply.** Designed operator + model on
> 2026-08-06 per skill §11 (schema-first, code-after). The DDL lives in
> [`schema/kernel.surql`](schema/kernel.surql); the operator applies it
> once under root via [`scripts/deploy-schema.sh`](scripts/deploy-schema.sh).
> From that moment the schema is locked: every change requires a fresh
> per-change `Operator-approved:` PR marker (skill §7, CI-enforced).

## 1. Contracts (binding on every kernel verb)

- **SurrealDB is the OS's filesystem.** One namespace `superx`, one
  database `kernel` for the kernel layer. Modules/adapters that need
  their own tables ship their own schemas + service accounts in later
  operator-approved PRs.
- **Append-only.** The service account's behavior contract is SELECT +
  CREATE. No kernel verb ever emits UPDATE, DELETE, UPSERT, DEFINE,
  REMOVE, or ALTER. Enforcement is kernel-verb discipline (SurrealDB's
  EDITOR role cannot be narrowed to insert-only for system users; the
  `FOR update/delete NONE` PERMISSIONS clauses below are documentation
  of intent).
- **SCD-2 by ordering, not by flags.** "Current" is always computed at
  read time: latest `valid_from` wins within a chain
  (`ORDER BY valid_from DESC LIMIT 1`). There are **no** `is_current` /
  `valid_to` columns — append-only forbids mutable currency flags, and
  advisory ones go permanently stale (v1 lesson).
- **UUIDv7 row ids, kernel-set.** Every row id is a UUIDv7 generated by
  the kernel at insert time — never SurrealDB auto-ids. Time-ordered
  ids make insertion order recoverable from the id itself.
- **Types flow end-to-end** (skill §14): `record<…>` FKs stay `Thing`
  in Rust, `datetime` stays `DateTime<Utc>`, `uuid` stays `Uuid`.
- **Facts, not judgments** (skill §9): a column records what happened
  or what is; rankings, priorities, and policy are never schema.

## 2. Service account

| | |
|---|---|
| User | `superx_kernel` (ON DATABASE) |
| Role | EDITOR |
| Password | `$SUPERX_KERNEL_PASSWORD`, substituted at deploy time; the kernel reads the same env var at signin. No literal ever lives in the repo. |
| Duration | `FOR TOKEN 1h, FOR SESSION NONE` — sessions never expire (operator decision 2026-08-06; v1's 1 h session killed long-running OS processes). Confirmed against SurrealDB docs: session duration `NONE` is valid and unexpiring. |

Root is operator-only, used exactly once per substrate to apply this
schema. The kernel signs in as `superx_kernel` forever after (skill §10/§13).

## 3. Tables (7)

Every table is SCHEMAFULL, global (single-operator OS, no tenancy), and
carries `valid_from: datetime` set by the kernel at insert.

### 3.1 `type_definition` — the metamodel
Types are data: new entity/edge/attribute types arrive by INSERT, never
DDL. **Immutable once created** (backed by the UNIQUE index): type
evolution means a new uid, or an operator-approved migration.

| field | type | constraint |
|---|---|---|
| `uid` | `string` | semantic key (`node_agent`, `attr_desc`, …); UNIQUE index |
| `category` | `string` | `node` \| `edge` \| `attribute` |
| `is_acyclic` | `bool` | meaningful for edge types |
| `sch_json` | `option<string>` | optional JSON-schema for payload validation |
| `memory_tier` | `string` | ASSERT ∈ `['core','working','archival','recall']` |

Kernel metamodel seed types are runtime INSERTs by the boot
orchestrator (G3), not DDL — they are listed in kernel code, not here.

### 3.2 `cursor_type` — cursor-kind metamodel
Same immutability + UNIQUE-uid contract as `type_definition`.

| field | type | constraint |
|---|---|---|
| `uid` | `string` | UNIQUE index |
| `category` | `string` | ASSERT ∈ `['workload','telemetry']` |
| `description` | `string` | |
| `sch_json` | `option<string>` | |

### 3.3 `entity` — identity (the persistent "who")
Agents, sources, modules, adapters, products, … — everything the OS
knows exists. Differentiated by `type`.

| field | type | constraint |
|---|---|---|
| `type` | `record<type_definition>` | ASSERT `$value.category = 'node'` |

### 3.4 `relation` — typed graph edges

| field | type | constraint |
|---|---|---|
| `in` | `record<entity>` | |
| `out` | `record<entity>` | |
| `type` | `record<type_definition>` | ASSERT `$value.category = 'edge'` |
| `is_acyclic` | `bool` | |

### 3.5 `state_ledger` — SCD-2 content (the versioned "what")
Every piece of state attached to an entity is a row here; new rows
supersede older ones per `(target, type)` chain.

| field | type | constraint |
|---|---|---|
| `target` | `record<entity>` | |
| `type` | `record<type_definition>` | ASSERT `$value.category = 'attribute'` |
| `payload` | `object FLEXIBLE` | shape enforced per attribute type by kernel-verb discipline |

Composite index `(target, type, valid_from)` backs the current-state
read path.

### 3.6 `cursor` — durable checkpoints
Append-only capture/workload checkpoints; the capture engine resumes
losslessly from the latest row per `(subject, cursor_type)`.

| field | type | constraint |
|---|---|---|
| `subject` | `record<entity>` | the source/run being checkpointed |
| `cursor_type` | `record<cursor_type>` | |
| `last_processed` | `option<string>` | opaque position token |
| `metadata` | `option<object> FLEXIBLE` | e.g. per-file offsets |

Composite index `(subject, cursor_type, valid_from)` backs the
latest-cursor read path.

### 3.7 `telemetry_stream` — the firehose
One row per event: every kernel mutation, every capture emission, every
lifecycle transition. Global, unscoped.

| field | type | constraint |
|---|---|---|
| `lifecycle_event` | `string` | event name (`transcript_event`, `module_active`, …) |
| `payload` | `any` | event body, tolerant by design |
| `subject` | `option<record<entity>>` | who emitted this — module, agent, or source; no type ASSERT |

Index on `valid_from` backs the stats/live poll path. Event rows are
never superseded — `valid_from` here is the event timestamp.

## 4. Indexes (5)

| index | table | fields | kind |
|---|---|---|---|
| `idx_type_definition_uid` | type_definition | uid | UNIQUE |
| `idx_cursor_type_uid` | cursor_type | uid | UNIQUE |
| `idx_state_ledger_chain` | state_ledger | target, type, valid_from | — |
| `idx_cursor_chain` | cursor | subject, cursor_type, valid_from | — |
| `idx_telemetry_valid_from` | telemetry_stream | valid_from | — |

The UNIQUE pair makes `ensure_*` find-then-create verbs race-safe
(cross-process double-creates surface as engine refusals — skill §12).
The three read-path indexes fix v1's measured full-scan behavior.

## 5. Deltas from v1 (`archive/pre-reset-2026-08-06`)

All operator-decided 2026-08-06 unless noted:

1. `schedule` and `execution_params` **dropped** — zero consumers
   existed; they re-enter via their own schema PR when the scheduler is
   designed against real requirements.
2. Session duration `1h` → **`NONE`** (token stays 1h).
3. **Five indexes added** (v1 had none).
4. `telemetry_stream.run` (ASSERT node_run) → **`subject`**, any
   entity, no ASSERT — capture-first attribution.
5. `entity.role` (ASSERT `['user','admin']`) **dropped** — vestigial
   v1 field with no consumer semantics (model-proposed; lands with this
   PR's operator approval).
6. `type_definition` / `cursor_type` are now formally
   **immutable-once-created** (consequence of the UNIQUE indexes).
7. Everything else is byte-equivalent in intent to v1's verified-live
   DDL.

## 6. Migration plan

None — fresh substrate. The v1 substrate data (default
`./db/superx.db`) is orphaned by the reset: it holds v1-schema rows the
v2 kernel never reads. Recommended: point the v2 server at a fresh path
(e.g. `rocksdb:./db/superx-v2.db`) and archive or delete the old
directory at the operator's convenience. Nothing in v2 migrates v1 rows.
