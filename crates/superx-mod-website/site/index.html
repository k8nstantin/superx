The agentic OS.

SuperX watches every agent on your machine — every conversation, every action, live. Then it puts them to work: model the work as a graph, schedule it, and agents execute it while the OS records them doing it. Nothing is ever lost — every change is an insert.

Concept

Capture everything. Then direct it.

Coding agents already run on your machine — Claude Code, Gemini CLI, Claude Desktop. SuperX boots, discovers them, and captures everything they emit: full conversations, tool calls, telemetry, historical and live. The substrate is append-only SurrealDB — every fact is an insert, every identity a uuid7, so the history of your agents is a permanent, queryable log.

Then the loop closes. You model work as a graph of entities — products contain components, tasks carry instructions, tasks consult RAGs, repos link credentials. The runner schedules the graph: independent tasks in parallel, dependencies in order, each executed by a spawned agent — whose session SuperX captures on its own dashboard. The OS directs work and watches itself do it.

Capabilities

What it does

◉

Total capture

Every conversation and action from Claude Code, Gemini CLI, and Claude Desktop — backfilled history plus a live stream, sessions identified agent/uuid7.

▦

Live dashboard

A Mantine/React module on its own port: status, charts, session liveness, every captured event streaming over SSE, CLI commands from the browser.

◈

Entity graph

Typed nodes — product, task, rag, model, repo, credential, text — linked by native graph edges. Descriptions and comments are nodes too; documents attach as nodes.

⇶

Runner

Schedule any entity. The runner plans waves over depends_on, dispatches agents in parallel, writes results back as produced nodes, recurs with every:.

▤

Pluggable modules

Every capability beyond capture is a module with its own database, service account, dir, log, CLI namespace, and parameters. Contribute one from a template.

∞

Nothing lost, ever

Append-only SCD-2 everywhere: updates insert versions, unlinks insert retractions, cancels append rows. Time-ordered uuid7 ids make the substrate a historical log.

How it works

A kernel, and everything else is a module

L1
Kernel — boot, discovery, the capture engine, the telemetry firehose, the append-only substrate verbs. The hub every module talks through.
L2
Adapters — per-agent capture: Claude Code, Gemini CLI, Claude Desktop. Tolerant parsers, cursor checkpoints, history backfill.
L3
Modules — ui, entities, runner, website… each self-contained with its own database and CLI, enable/disable live, several of a kind side by side.
L4
Agents — spawned by the runner, observed by the adapters: the loop that makes it an OS rather than a logger.
