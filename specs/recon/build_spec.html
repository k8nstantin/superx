Recon Build Spec

Version 0 · epic #466 · 2026-10-26 · rendered from specs/recon/ at 001990b. An agent reads the rules, the root, its one task file and the code merged on main, and nothing else.

The models, the agents, thinking effort and the operator, measured. One crawler crawls every line the kernel captured, every repository those lines lead to and every host those repositories live on, in depth, into one structure, and the module reports on it in its own tab, on its own port. The crawler is the only thing in the module that reads: it finds the details that are not readily apparent, ties what the agents did to what became of their work, and delivers the critical data no one knew to look for.

The build

The sequence

Four tasks, four PRs at most: the structure first, whole, before anything fills it; then the crawler that fills it, the lines in one task and the repositories with their hosts in the next; then the tab, designed with the operator once the crawler is merged. Each task is one build an agent does from its file; the operator deploys and runs what it builds. A task starts when the task before it is merged on main. Its file under tasks/ carries, verbatim, what the structure and the authority files say about its piece, what it builds, its gates and what it owns; this list carries the piece, the files it reflects and what it builds.

The decisions

What was decided, when, and where it lives; what is still open. A confirmed decision is written into the file or element named, which is the authority; it is listed here so an agent knows a question is closed. An open decision is a question an agent never answers: a task that needs it stops. An open decision names in closes-before the task before whose file it is closed, and check.py refuses that file while the decision is open.
